# Quản lý bản dịch giao diện

Các bản dịch giao diện được lưu tại:

```text
public/i18n/vi.json
public/i18n/en.json
public/i18n/zh.json
```

`LanguageService` tải file theo mã ngôn ngữ và cache trong bộ nhớ. Bản dịch giao
diện không được ghi vào MySQL hoặc local storage.

## Cập nhật các file hiện có

Sau khi thêm một lời gọi `language.choose(vietnamese, english)`, chạy:

```bash
npm run i18n:generate
```

Script bổ sung key ổn định vào các file JSON. Với ngôn ngữ ngoài Việt/Anh, giá
trị mới chưa được dịch sẽ tạm dùng tiếng Anh để người dịch dễ tìm và hoàn thiện.

## Thêm ngôn ngữ mới thủ công

Ví dụ tiếng Nhật:

1. Tạo `public/i18n/ja.json` với cùng tập key trong `en.json`.
2. Dịch toàn bộ value và giữ nguyên key.
3. Thêm/kích hoạt tiếng Nhật trong trang Admin.
4. Khi trạng thái là `READY`, ngôn ngữ xuất hiện trên topbar.

## Tự động hóa ngôn ngữ mới

Việc thêm một dòng vào bảng `languages` chỉ tạo lựa chọn ngôn ngữ; nó không tự
sinh bản dịch chính xác. Luồng tự động nên được triển khai phía backend:

1. Đọc gói nguồn `en.json`.
2. Gửi từng nhóm value tới nhà cung cấp dịch máy.
3. Kiểm tra đủ key và giữ nguyên placeholder.
4. Lưu JSON vào object storage/CDN theo đường dẫn ổn định
   `i18n/{language-code}.json`.
5. Chỉ chuyển ngôn ngữ sang `READY` sau khi file hợp lệ.
6. Frontend tải URL JSON đó khi người dùng chọn ngôn ngữ.

Không nên ghi file mới trực tiếp vào thư mục Angular khi ứng dụng đang chạy vì
GitHub Pages và đa số môi trường production có filesystem chỉ đọc.
